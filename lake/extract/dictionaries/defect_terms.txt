# defect_terms.txt - keyword rules for lake/process/DefectClassify.scala
#
# Format: section|term|value   (terms are matched as whole words, case is ignored)
#
# system     the EARLIEST system term in the note decides the system, because technicians
#            start a defect note with the system ("hyd press low LH sys, topped up")
# component  the LONGEST matching term decides the component (the most specific one).
#            A term written SYSTEM:term only applies to notes of that system
# default    component used when no component term matches: default|SYSTEM|component
# severity   the HIGHEST severity among the matching terms (AOG > HIGH > MEDIUM > LOW);
#            notes without a severity term get default_severity. Used where the maintenance
#            system left the severity empty, and compared with it where it did not
# All rules are project assumptions [A], written from common maintenance vocabulary.
